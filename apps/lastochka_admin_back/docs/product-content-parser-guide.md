# Выгрузка номенклатуры для парсера и обратный импорт (LASTOCHKI-JAMI-12027)

## Файл выгрузки

XLSX, кодировка UTF-8, два листа:
- **Товары** — вся номенклатура (включая скрытые товары), 29 колонок;
- **Инструкция** — правила заполнения каждой колонки.

Получение: `php artisan products:export-content [--only-unfilled] [--path=...]`
(`--only-unfilled` — только товары, где не хватает контента: описание,
атрибуты БЖУ/хранение, фото; SEO-поля meta_* в критерий не входят).

## Структура колонок

| Группа | Колонки | Что делать парсеру |
|---|---|---|
| Ключ | id | НЕ МЕНЯТЬ — по нему обратный импорт |
| Справочные | Название, Артикул, Код 1С, Штрих-коды, Категория, Ед. измерения, Вес, Цена, Остаток, Статус, Удалён, % заполнения, Есть фото | Только для идентификации товара, менять бессмысленно — импорт игнорирует |
| Заполняемые | Описание, Белки, Жиры, Углеводы, Ккал, Состав, Условия хранения, Срок хранения, Вес брутто, Вес нетто, Габариты, Фото (URL), meta_title, meta_description, meta_keywords | Заполнять ПУСТЫЕ ячейки |

Форматы значений:
- БЖУ и Ккал — число на 100 г, точка или запятая («8,6»), допустим суффикс
  единицы («8,6 г», «250 ккал»);
- строковые поля (Условия/Срок хранения, брутто/нетто, Габариты, meta_title) — до 255 символов;
- Описание и Состав — без ограничения длины, без HTML;
- Если данных нет — оставляйте ячейку пустой, НЕ пишите 0: одиночный 0
  считается заглушкой и игнорируется импортом. Реальное нулевое значение БЖУ
  указывайте с единицей: «0 г».

## Фотографии

- В колонке «Фото (URL)» — прямые http(s)-ссылки на изображения, **каждая с
  новой строки** внутри ячейки (Alt+Enter в Excel).
- Форматы: jpg / png / webp, размер до ~10 МБ.
- **Первая ссылка станет главным фото**, остальные — галерея.
- Фото добавляются только товарам, у которых «Есть фото» = 0. Существующие
  фото система не заменяет и не дополняет.

## Обратный импорт

`php artisan products:import-content <файл.xlsx> [--dry-run] [--overwrite]`

- Сопоставление строго по `id`. Новые товары НЕ создаются, дубли невозможны.
- Записываются только ПУСТЫЕ поля (ручные правки в админке между выгрузкой
  и импортом не затираются). `--overwrite` — явная перезапись непустых.
- Пустая ячейка файла никогда не стирает данные в системе.
- Импорт НЕ трогает: активность товара (ручной флаг), артикул, название,
  штрих-коды, цены, остатки, категории, единицы измерения.
- Первый запуск — всегда `--dry-run` (проверка без записи).
- Результат: сводка в консоли + CSV-отчёт рядом с файлом
  (`id; строка; поле; статус updated/skipped_filled/error; причина`).
- После импорта изменения автоматически пересчитывают % заполнения карточки
  и синхронизируются в интернет-магазин (storefront) через RabbitMQ.
