# Приложение A: Формат CommerceML

## Обзор

CommerceML — стандарт обмена коммерческой информацией, разработанный 1С. Используется для обмена каталогами товаров, ценами, остатками и заказами.

---

#### Цены от количества (кастомный реквизит `<ЦеныОтКоличества>`, MID-308)

Лесенка «цена за единицу зависит от количества в позиции» передаётся внутри блока `<Цена>`, рядом с `<ЦенаЗаЕдиницу>`:

```xml
<Цена>
    <ИдТипаЦены>price-retail</ИдТипаЦены>
    <ЦенаЗаЕдиницу>279.00</ЦенаЗаЕдиницу>
    <ЦеныОтКоличества>
        <ЦенаОтКоличества>
            <Количество>2</Количество>
            <ЦенаЗаЕдиницу>249.00</ЦенаЗаЕдиницу>
        </ЦенаОтКоличества>
        <ЦенаОтКоличества>
            <Количество>5</Количество>
            <ЦенаЗаЕдиницу>199.00</ЦенаЗаЕдиницу>
        </ЦенаОтКоличества>
    </ЦеныОтКоличества>
    <Валюта>RUB</Валюта>
</Цена>
```

Правила:

- `<Количество>`: порог «от», в базовых единицах товара (шт, кг, л), может быть дробным (`2,5` или `2.5`). `<ЦенаЗаЕдиницу>` внутри ступени: цена за ту же базовую единицу, что и основная `<ЦенаЗаЕдиницу>` блока.
- Цена ступени действует на все единицы позиции, ступень выбирается по количеству товара в позиции заказа.
- Порог и цена больше нуля и не больше верхней границы (`9999999.999` для порога, `9999999999.99` для цены, это разрядность колонок хранения), пороги внутри одного блока `<Цена>` не повторяются. Число ступеней в одном блоке не больше 50, лесенка длиннее лимита отбрасывается целиком. Порог и цена обязаны быть числом: нечисловое значение (например, `5kg` или `1 000` с пробелом как разделителем разрядов) тоже отбрасывает лесенку целиком. Лесенка с ошибкой отбрасывается целиком с предупреждением в логе `1c-exchange`: сохранённые ступени не меняются, основная цена блока применяется как обычно. Убывание цен по ступеням не проверяется.
- Лесенка передаётся целиком при каждой выгрузке цены. Тега `<ЦеныОтКоличества>` нет, либо он есть, но полностью пустой (нет дочерних элементов): у товара, у которого ступени были, лесенка удаляется, у товара без ступеней ничего не меняется. Если тег есть и внутри него ЕСТЬ дочерние элементы, но среди них нет ни одного `<ЦенаОтКоличества>` (например, опечатка в имени вложенного тега): это не очистка, а битая лесенка, сохранённые ступени не меняются, применяется правило «Лесенка с ошибкой» выше.
- Лесенка хранится по типу цены (`ИдТипаЦены`), на витрину уходит лесенка только розничного типа (`ONEC_RETAIL_PRICE_TYPES`, тот же тип, из которого берётся витринная цена).
- Рекомендация: если лесенка начинается «от 1», держать цену первой ступени равной основной `<ЦенаЗаЕдиницу>`.

## Протокол обмена

### Этапы

| Шаг | Запрос | Описание |
|-----|--------|----------|
| 1 | `GET ?type=catalog&mode=checkauth` | Авторизация |
| 2 | `GET ?type=catalog&mode=init` | Инициализация, получение параметров |
| 3 | `POST ?type=catalog&mode=file&filename=import.xml` | Загрузка файла |
| 4 | `GET ?type=catalog&mode=import&filename=import.xml` | Запуск импорта |

### Ответы сервера

**checkauth (успех):**
```
success
PHPSESSID
session_id_value
```

**init:**
```
zip=yes
file_limit=20000000
```

**file:**
```
success
```

**import:**
```
success
```
или
```
progress
Обработано 500 из 1000
```

## Особенности

### Кодировка

- Файлы могут приходить в **windows-1251** или **UTF-8**
- Проверять `encoding` в XML declaration
- Пакет `mavsan/laravel-1c-protocol` обрабатывает автоматически

### Характеристики товаров

Товар с характеристиками имеет составной ID:
```
<Ид>guid-товара#guid-характеристики</Ид>
```

### Изображения

- Путь относительный: `import_files/image.jpg`
- Файлы загружаются отдельно через `mode=file`
- Могут быть в ZIP-архиве

### Большие файлы

- Файлы разбиваются на части (chunked upload)
- Сервер должен склеивать части
- Параметр `file_limit` указывает максимальный размер части
