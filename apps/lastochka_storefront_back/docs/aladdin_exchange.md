# Архитектура Обмена, Аладдин

Данный документ описывает архитектуру и принципы обмена данными между ключевыми системами проекта: **RetailCRM**, **Bagisto**, **DeliverySystem** и брокером сообщений **RabbitMQ**.

Основная цель интеграции — обеспечить **надёжную, двустороннюю и независимую синхронизацию** данных между всеми участниками экосистемы без прямых связей между ними.  
Каждая система взаимодействует только с RabbitMQ.

Дополнительно в документе описана API интеграция между **Bagisto** и **DeliverySystem**. Данная интеграция не влияет на обмен данными, а предоставляет дополнительный функционал работы слотов доставки

## Элементы системы

- RetailCRM - CRM система
- Bagisto - интернет магазин
- DeliverySystem - система доставки
- RabbitMQ - брокер сообщений
- RetailBridge - сервис-прослойка между RetailCRM - RabbitMQ

## Состав обмена

- Товары
- Категории
- Заказы
- Клиенты
- Сотрудники
- Магазины

## API получения доступных слотов курьерской доставки.

Клиентская часть отправляет запрос с содержанием следующих полей

| Техническое название | Логическое название | Тип | Обязательное |
| --- | --- | --- | --- |
| latitude | Широта | Дробное число | Да  |
| longitude | Долгота | Дробное число | Да  |
| date | Дата доставки | Дата в формате Y-m-d (например 2022-12-30) | Да  |

**Бэкенд** клиентской части собирает корзину товара и внешние идентификаторы для системы доставки и отправляет запрос в **АПИ** системы доставки. Система доставки по полученным координатам производит поиск, находятся ли координаты в какой-либо зоне, если да то собирает доступные **слоты** на 7 дней, начиная от отправленного дня

Формат ответа

```json
{
  "slots" : [
    {
```

Получение списка магазинов с графиком работы самовывоза.

### Параметры запроса

Нет

### Ответ

```json
{
  "data": [
    {
      "id": 1,
      "code": "main",
      "title": "Название магазина",
      "address": "Адрес магазина",
      "pickup_hours": [
        {
          "day_of_week": 1,
          "type_id": 2,
          "opening_time": "09:00:00",
          "closing_time": "21:00:00"
        }
      ]
    }
  ]
}
```

### Поля ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | ID магазина |
| `code` | string | Уникальный код магазина |
| `title` | string | Название магазина |
| `address` | string | Адрес магазина |
| `pickup_hours` | array | График работы самовывоза |
| `pickup_hours[].day_of_week` | integer | День недели (1=Пн, 7=Вс) |

| `pickup_hours[].closing_time` | string\|null | Время закрытия (HH:MM:SS) |

### HTTP коды

- `200` — успех

## Регистрация событий в RMQ

Любой узел системы при следующих событиях отправляет данные в RMQ

### **1\. Товары (**`product.*`**)**

| Событие | Когда отправлять |
| --- | --- |
| `product.created` | Когда создан новый товар в системе (впервые добавлен в каталог) |
| `product.updated` | При изменении цены, остатков, описания, фото, SEO, SKU и т.п. |
| `product.deleted` | Когда товар удалён или деактивирован |
| `product.stock.changed` | При изменении остатков в магазине (1С, RetailCRM, сайт) |

---

### **2\. Категории (**`category.*`**)**

| Событие | Когда отправлять |
| --- | --- |
| `category.created` | Создана новая категория / подкатегория |
| `category.updated` | Изменено название, порядок, SEO |
| `category.deleted` | Категория удалена или скрыта |

---

### **3\. Заказы (**`order.*`**)**

| Событие | Когда отправлять |
| --- | --- |
| `order.created` | Заказ создан (клиент оформил или менеджер добавил) |

| `order.cancelled` | Заказ отменён пользователем или менеджером |

## RetailBridge - сервис-прослойка

**RetailBridge** - это сервис-прослойка, который обеспечивает двусторонний обмен данными между **RabbitMQ** и **RetailCRM**.  
Он выступает посредником между событийной шиной и CRM, синхронизируя заказы, клиентов, статусы и другие сущности.

---

### Основные функции

- **Приём событий из RabbitMQ**  
    Обрабатывает сообщения из очередей и конвертирует их в REST-запросы к RetailCRM API.
- **Отправка событий в RabbitMQ**  
    Принимает вебхуки и уведомления из RetailCRM (создание/изменение заказов, клиентов, статусов) и публикует соответствующие события обратно в RabbitMQ.
- **Хранение маппингов**  
    Ведёт соответствие ID между RetailCRM и другими системами (например, ID клиента в CRM ↔ ID во внешней системе)
