# Чек: стоимость позиции в строке (клиентское приложение)

Дата: 10.09.2026
Экран: «Чеки» (`lib/pages/receipts/view/widgets/_receipt_card.dart`)
Бэкенд: `lastochka_storefront_back`, ветка `feat/receipt-line-sum`

## Проблема

Сейчас справа в строке позиции приложение рисует `items[].amount`, а это **цена за единицу**, не стоимость позиции. Количество показано отдельной серой строкой «× 2» под названием, поэтому покупатель читает «81 ₽» как то, что он заплатил за макароны, и итог чека у него не сходится.

Пример из прод-чека (заказ 199, ФД 144, 2 636.18 ₽):

```
Макароны Гео-простор Яичная 500г хинкал          81 ₽     <- показано
× 2
НДС 10% · 14.73 ₽
```

В чеке за эту позицию списано 162 ₽.

Второй дефект того же экрана: у весовых позиций бэкенд отдаёт единицу измерения в `items[].unit`, но модель `ReceiptItem` этого поля не содержит, поэтому «Баклажан» показан как «× 2.024» вместо «× 2.024 кг».

## Что должно получиться

```
Макароны Гео-простор Яичная 500г хинкал         162 ₽     <- sum, жирным
2 × 81 ₽                                                  <- вторичным цветом
НДС 10% · 14.73 ₽

Баклажан                                     200.38 ₽
2.024 кг × 99 ₽
НДС 10% · 18.22 ₽
```

Правила:

1. Справа в строке выводить `items[].sum` (стоимость позиции), выделенным начертанием. Сейчас там `amount`.
2. Под названием выводить разбор «`quantity` [`unit`] × `amount` ₽». Единицу подставлять, только если `unit` не пустой.
3. Когда `quantity` равно 1, разбор не показывать (как сейчас): справа стоит `sum`, он же равен цене.
4. Строка НДС остаётся без изменений.

## Контракт ручки

`GET /api/v1/orders/{orderId}/receipts`
Base URL: `https://lastochki.store` (прод), `https://store.djami.comrades.dev` (dev)
Auth: `Authorization: Bearer <token>`

`200` (пример сокращён до двух позиций, суммы согласованы между собой):

```json
{
  "data": [
    {
      "type": "payment",
      "status": "succeeded",
      "registered_at": "2026-09-10T18:09:00+03:00",
      "total": "362.38",
      "items": [
        {
          "description": "Макароны Гео-простор Яичная 500г хинкал",
          "quantity": "2.00",
          "amount": "81.00",
          "sum": "162.00",
          "unit": null,
          "vat_code": 3,
          "vat_rate": "10",
          "vat_amount": "14.73"
        },
        {
          "description": "Баклажан",
          "quantity": "2.024",
          "amount": "99.00",
          "sum": "200.38",
          "unit": "кг",
          "vat_code": 3,
          "vat_rate": "10",
          "vat_amount": "18.22"
        }
      ],
      "vat": [{ "vat_code": 3, "rate": "10", "amount": "32.95" }],
      "vatTotal": "32.95",
      "fiscal": { "fn": "7381440901341940", "fd": "144", "fp": "2522577294" },
      "receiptUrl": "https://consumer.1-ofd.ru/v1?fn=...",
      "qr": "t=20260910T180900&s=362.38&fn=...&i=144&fp=...&n=1",
      "seller": { "name": "ИП Мамаева Т.Ш.", "inn": "070602943656" }
    }
  ]
}
```

Поля позиции:

| Поле | Тип | Что это |
|---|---|---|
| `description` | string | Наименование |
| `quantity` | string | Количество. Штучные: «1.00», «2.00». Весовые: в кг или л с точностью до грамма, «0.63», «2.024» |
| `amount` | string | Цена за единицу (за штуку, за кг, за литр) |
| `sum` | string | **Новое.** Стоимость позиции ровно как в фискальном документе |
| `unit` | string, null | «кг», «л» или `null` для штучных. У чеков, пробитых до августа, ключа может не быть |
| `vat_code` | int | Код ставки: 1 без НДС, 2 ноль, 3 десять процентов, 4 двадцать, 11 двадцать два |
| `vat_rate` | string, null | Ставка в процентах: «10», «20», «22», «0». `null`, если ставка неизвестна |
| `vat_amount` | string | Сумма НДС по позиции, включённая в стоимость |

Важно про `sum`:

- поле присутствует **всегда**, в том числе у чеков, пробитых до этой правки (там оно восстанавливается бэкендом);
- считать `amount × quantity` на клиенте нельзя. Цена весовой позиции производна от суммы (`round(sum / quantity, 2)`), и касса допускает расхождение произведения с суммой строки до копейки. Пример: `sum` = 141.53, `quantity` = 2.51 кг, `amount` = 56.39, произведение даёт 141.54, то есть на копейку больше, чем напечатано в чеке.

## Модель в приложении

`lib/data/domain/receipt/models/receipt_item.dart`:

- поле `amount` сейчас документировано как «Сумма по позиции», это неверно, там цена за единицу;
- добавить `sum` (double) и `unit` (String?).

## Проверка

Тестовый чек на dev получить по рецепту cash-заказа, либо открыть любой существующий заказ с чеком. Проверить: штучная позиция с количеством больше 1, весовая позиция (килограммы), позиция с количеством 1 (разбор не показывается), чек возврата (суммы со знаком минус, как сейчас).
