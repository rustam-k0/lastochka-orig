# Карточка товара: бонусы, сроки доставки/самовывоза, признак сравнения

**Дата:** 2026-07-31
**API:** `electrohub_storefront_back` (REST)
**Тип:** новые поля в ответе товара + новый query-параметр + исправление авторизации на публичных ручках товара

Контракт изменённого API для мобильного приложения. Описывает, что отдаёт бэкенд.

## Что изменилось

1. В объекте товара появилось поле `bonusEarn` (int) с количеством бонусов за единицу товара. Присутствует всегда, дополнительных параметров не требует.
2. В объекте товара появилось поле `storeId` (int) с идентификатором магазина.
3. В объекте товара появилось поле `isInComparison` (bool): лежит ли товар в сравнении текущего пользователя. Присутствует всегда, для запроса без токена равно `false`.
4. Поля `deliveryDate` и `pickupDate` (раньше отдавались только в листинге категории) теперь отдаются также на карточке товара, в похожих, в сопутствующих и в поиске по штрихкоду. Условие прежнее: передан `cityId`.
5. Параметр `cityId` добавлен в `GET /products/{id}`, `GET /products/{id}/similar`, `GET /products/{id}/related`, `GET /products/search/barcode/{barcode}`.
6. Публичные ручки товара теперь разбирают `Authorization: Bearer <token>`. Раньше токен на них игнорировался, поэтому `isFavorite` всегда возвращался `false`, даже если товар лежал в избранном. Теперь `isFavorite` и `isInComparison` отражают состояние пользователя, приславшего токен.

Существующие поля и ручки не менялись.

## База

| | |
|---|---|
| Dev | `https://api.electrohub.comrades.dev` |
| Префикс | `/api/v1` |
| Протокол | REST, `application/json` |
| Auth | не требуется. Токен опционален: `Authorization: Bearer <token>` включает персональные признаки `isFavorite` и `isInComparison`, без токена оба `false` |
| Rate limit | нет |

## Ручки

### GET /api/v1/products/{id}: карточка товара

| Параметр | Тип | Обяз. | Описание |
|---|---|---|---|
| `cityId` | int | нет | Город для расчёта `deliveryDate` / `pickupDate`. Без параметра оба поля в ответе отсутствуют. Snake_case-вариант `city_id` принимается как алиас. |

Ответ: `{ "data": Product }`.

### GET /api/v1/products/{id}/similar: похожие товары

Параметры: `page`, `perPage` (max 50), `onlyDiscounted`, `sugarFree`, `cityId`.
Ответ: `{ "hasMore": bool, "data": Product[], "total": int }`.

### GET /api/v1/products/{id}/related: сопутствующие товары

Параметры: `productsLimit` (max 9), `cityId`.
Ответ: `{ "data": [ { "id": int, "name": string, "slug": string, "products": Product[] } ] }`.

### GET /api/v1/products/search/barcode/{barcode}: поиск по штрихкоду

Параметры: `cityId`.
Ответ: `{ "data": Product }`.

### GET /api/v1/stores/{store}/categories/{category}/products: листинг категории

Параметр `cityId` работал и раньше. Товары в ответе теперь содержат `bonusEarn` и `storeId`.

### GET /api/v1/cities: список городов

Источник значений для `cityId`. Ответ: `{ "data": [ { "id": int, "name": string, "latitude": float, "longitude": float, "isDefault": bool } ] }`.

### GET /api/v1/stores/{storeId}/bonus-settings: настройки бонусов магазина

Ручка существовала ранее, не менялась. Публичная. Ответ:

```json
{ "data": { "isEnabled": true, "earnPercent": 5, "spendPercent": 20 } }
```

При выключенных бонусах: `isEnabled: false`, оба процента `0`.

## Тип Product (изменённые и относящиеся к теме поля)

```
Product {
  id: int
  storeId: int          # новое; может быть null
  price: float
  priceOld: float|null
  discountPercent: int|null
  bonusEarn: int        # новое; 0 если начисления нет
  isFavorite: bool      # существовало; с этой версии учитывает Bearer-токен
  isInComparison: bool  # новое; false без токена
  deliveryDate: string|null   # "YYYY-MM-DD"; ключ присутствует только при переданном cityId; может быть null
  pickupDate: string|null     # "YYYY-MM-DD"; ключ присутствует только при переданном cityId; может быть null
  variants: [ { id, sku, title, price, priceOld, bonusEarn, stockQuantity, availability, images, attributes, isDefault } ]
}
```

Поле `bonusEarn` присутствует и внутри каждого элемента `variants` у вариативного товара, со значением для цены конкретного варианта.

## Поведение сервера

### bonusEarn

| Условие | Значение `bonusEarn` |
|---|---|
| Бонусы магазина включены, у товара нет скидки | `floor(price * earnPercent / 100)` |
| У товара есть скидка (`priceOld != null`, то есть ручная скидка или активная акция) | `0` |
| Бонусы магазина выключены | `0` |
| У товара нет магазина | `0` |

Правило «за товары со скидкой бонусы не начисляются» действует и при оформлении заказа: в расчёт бонусов попадают только позиции без скидки, поэтому `bonusEarn` на карточке согласован с суммой начисления в корзине.

Значение считается по цене единицы товара. Итог по позиции с количеством больше единицы сервер на этой ручке не отдаёт, суммы по корзине приходят в ответе корзины (`bonus.maxEarn`).

### isInComparison

| Условие | Значение `isInComparison` |
|---|---|
| Запрос без токена | `false` |
| Товар лежит в сравнении пользователя, приславшего токен | `true` |
| Товар не добавлен в сравнение либо лежит в сравнении другого пользователя | `false` |

Признак не зависит от категории группы сравнения: товар считается добавленным, если он есть в любой группе этого пользователя. Управление составом сравнения прежнее: `POST /api/v1/comparisons/items` и `DELETE /api/v1/comparisons/items/{productId}` (обе под `auth:sanctum`, throttle 60/мин).

### deliveryDate / pickupDate

| Условие | Что отдаёт сервер |
|---|---|
| `cityId` не передан | Ключей `deliveryDate` и `pickupDate` в ответе нет |
| `cityId` передан, город не найден или у него нет координат | Ключей в ответе нет |
| `cityId` передан корректно | Оба ключа присутствуют |
| Есть слот доставки на сегодня | `deliveryDate` = сегодняшняя дата |
| Слотов сегодня нет, есть завтра | `deliveryDate` = завтрашняя дата |
| Слотов нет ни сегодня, ни завтра, либо сервис слотов недоступен | `deliveryDate: null` |
| Самовывоз у магазина выключен | `pickupDate: null` |
| Самовывоз включён | Ближайшая дата со слотами в пределах 7 дней, иначе `null` |

Даты определяются магазином товара и координатами города, а не адресом пользователя. Результат кешируется на стороне сервера 30 минут.

## Коды ответов

| Ситуация | HTTP | Тело |
|---|---|---|
| Успех | 200 | `{ "data": ... }` |
| Товар не найден, удалён или неактивен | 404 | `{ "message": "No query results for model [App\\Models\\Product] {id}" }` |
| Товар отсутствует на складе при выключенном модуле предзаказов | 404 | то же |
| Штрихкод не найден | 404 | `{ "message": "Товар с указанным штрихкодом не найден" }` |
| Магазин не найден, неактивен или скрыт B2B-фильтром (`bonus-settings`) | 404 | стандартный ответ Laravel |

## Пример

```bash
curl "https://api.electrohub.comrades.dev/api/v1/products/53480?cityId=1" \
  -H "Authorization: Bearer <token>"
```

```json
{
  "data": {
    "id": 53480,
    "storeId": 1,
    "title": "Лампочка Эра",
    "price": 500,
    "priceOld": null,
    "discountPercent": null,
    "bonusEarn": 25,
    "isFavorite": true,
    "isInComparison": true,
    "deliveryDate": "2026-07-31",
    "pickupDate": null
  }
}
```

Без `cityId` тот же товар возвращается без ключей `deliveryDate` и `pickupDate`, поле `bonusEarn` остаётся на месте. Без заголовка `Authorization` поля `isFavorite` и `isInComparison` равны `false`, остальные значения не меняются.

## Обратная совместимость

Изменения аддитивные: `bonusEarn`, `storeId` и `isInComparison` добавлены в объект товара, существующие поля, их типы и семантика не менялись. Ручки, параметры и коды ответов прежние, `cityId` опционален. Клиент, не знающий о новых полях, продолжает работать без изменений.

Отдельно про `isFavorite`: тип и место поля прежние, изменилось только то, что на публичных ручках товара оно теперь учитывает переданный Bearer-токен. Клиент без токена получает `false`, как и раньше.
