## Архитектура платежей

### Текущее понимание

```
1. Клиент добавляет карту → Эквайринг (CloudPayments/ЮKassa)
2. Эквайринг возвращает токен карты
3. Бэкенд сохраняет: last4, cardType, token
4. При оплате: списание по токену
5. В Exchange: payment_type=card, is_paid=true
```

### Вопросы

1. **Какой эквайринг используется?**
   - CloudPayments
   - ЮKassa
   - Тинькофф
   - Другой

2. **Рекуррентные платежи или разовые?**

## Рекомендации

### 1. Интеграция с эквайрингом

```
PaymentCard:
  - id: int
  - user_id: int
  - last4: string
  - card_type: string (Visa/MasterCard/Mir)
  - token: string (encrypted) — для рекуррентов
  - is_active: bool
  - created_at: timestamp
```

### 2. Процесс оплаты заказа

```
1. createOrder() — создаёт заказ со статусом pending
2. Если payment_type=card:
   a. Инициирует платёж через эквайринг
   b. При успехе: order.is_paid=true, отправить order.paid
   c. При ошибке: вернуть ошибку клиенту
3. Если payment_type=cash:
   a. order.is_paid=false
   b. Оплата при получении
```

### 3. События для Exchange

При успешной оплате отправлять:
```json
{
  "event": "order.paid",
  "order_id": "...",
  "payment_type": "card",
  "is_paid": true
}
```
