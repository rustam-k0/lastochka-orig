# Анализ: Авторизация и Профиль

## Экраны дизайна
- **АВТОРИЗАЦИЯ** — ввод телефона, ввод OTP-кода
- **ПРОФИЛЬ** — личные данные пользователя, редактирование

---

## Сопоставление: API ↔ Exchange ↔ Дизайн

### 1. Авторизация по телефону

| Источник | Данные |
|----------|--------|
| **API** | `phoneLogin(phone)` → OTP код, `phoneConfirm(phone, code)` → `LoginResponse{token, user}` |
| **Exchange** | Не участвует в авторизации (только синхронизация клиентов) |
| **Дизайн** | Экран ввода телефона → Экран ввода кода |

**✅ Статус:** Полностью покрыто API. Авторизация — локальная логика бэкенда.

---

### 2. Профиль пользователя

| Поле | API (User) | Exchange (customers) | Дизайн | GAP |
|------|------------|---------------------|--------|-----|
| id | ✅ int | ✅ string | — | Разные типы ID |
| phone | ✅ | ✅ | ✅ | — |
| firstName | ✅ | ✅ name | ✅ | Маппинг name↔firstName |
| lastName | ✅ | ✅ surname | ✅ | Маппинг surname↔lastName |
| email | ✅ | ✅ | ✅ | — |
| birthDate | ✅ DateTime | ✅ birthday (Date) | ✅ | — |
| gender | ✅ male/female/other | ✅ male/female | ✅ | **API имеет `other`, Exchange — нет** |
| patronymic | ❌ | ✅ | ❓ | **Не в API, есть в Exchange** |

## Критические вопросы

### ❓ Вопрос 1: Отчество (patronymic)
**Проблема:** Exchange поддерживает `patronymic`, API — нет.
- Есть ли в дизайне поле "Отчество"?
- Нужно ли добавить в API?

### ❓ Вопрос 2: Gender = "other"
**Проблема:** API поддерживает `other`, Exchange только `male/female`.
- Что делать при синхронизации, если пользователь выбрал "other"?
- Рекомендация: убрать `other` из API или добавить в Exchange.

### ❓ Вопрос 3: ID пользователя
**Проблема:** API использует `int`, Exchange — `string`.
- Нужен маппинг ID между системами.
- Рекомендация: хранить `external_id` (string) для связи с CRM.

---

## Рекомендации для бэкенда

1. **Таблица users:**
   - Добавить `patronymic` (nullable)
   - Добавить `external_id` (string, nullable) для связи с RetailCRM
   - Добавить `source` (string) — канал создания

2. **События RabbitMQ:**
   - `customer.created` — при регистрации нового пользователя
   - `customer.updated` — при изменении профиля

3. **Маппинг полей при синхронизации:**
   ```
   API.firstName ↔ Exchange.name
   API.lastName ↔ Exchange.surname
   API.birthDate ↔ Exchange.birthday
   ```
