## Сопоставление: Часы работы

### API (WorkingHours)
```json
{
  "openingHour": 9,
  "openingMinute": 0,
  "closingHour": 21,
  "closingMinute": 0
}
```

### Exchange (schedule)
```json
{
  "monday": {"start": "10:00", "end": "20:00"},
  "tuesday": {"start": "10:00", "end": "20:00"},
  "wednesday": {"start": "10:00", "end": "20:00"},
  "thursday": {"start": "10:00", "end": "20:00"},
  "friday": {"start": "10:00", "end": "20:00"},
  "saturday": {"start": "11:00", "end": "18:00"},
  "sunday": null
}
```

### GAP анализ

**Проблема:** API предполагает одинаковое время каждый день, Exchange — разное по дням недели.

**Вопросы:**
- Нужен ли клиенту график по дням недели?
- Или достаточно "сегодня открыто до XX:XX"?

**Рекомендации:**

**Вариант 1:** Расширить API WorkingHours
```json
{
  "schedule": {
    "monday": {"open": "10:00", "close": "20:00"},
    "tuesday": {"open": "10:00", "close": "20:00"},
    ...
  },
  "isOpenNow": true,
  "todayHours": "10:00 - 20:00"
}
```

**Вариант 2:** Оставить простую модель, вычислять на бэке
- Хранить полный schedule в БД
- API возвращает "текущие часы работы" на основе дня недели

## 🔴 Критические проблемы

### 1. Минимальная сумма заказа (minOrderAmount)
**Проблема:** API требует `minOrderAmount`, Exchange не передаёт.

**Вопросы:**
- Откуда брать минимальную сумму?
- Из DeliverySystem (`min_order_price`) или из CRM?

**Рекомендация:** Использовать данные из DeliverySystem API:
```json
{
  "min_order_price": 500,
  "shipping_free_from": 1500,
  "shipping_price": 200
}
```

### 2. Изображение магазина (image)
**Проблема:** API требует `image`, Exchange не передаёт.

**Вопросы:**
- Откуда брать логотип/фото магазина?
- Загружается отдельно?

**Рекомендация:** Добавить поле в Exchange или загружать через админку.

### 3. Рейтинг магазина (rating)
**Проблема:** API требует `rating`, Exchange не передаёт.

**Вопросы:**
- Как считается рейтинг?
- На основе отзывов?
- Есть ли экран ОТЗЫВЫ в дизайне?

**Рекомендация:** 
- Если есть отзывы: считать средний рейтинг
- Если нет: убрать из API или сделать nullable

### 4. Уникальный код магазина (shop_code)
**Проблема:** Exchange использует `shop_code` для связи, API использует `id`.

**Рекомендация:** Добавить `code` в API Store:
```json
{
  "id": 1,
  "code": "SHOP_MSK_001",
  "name": "Магазин №1"
}
```

## Связь магазина с другими сущностями

```
Store
├── Categories[] — категории этого магазина
├── Products[] — товары этого магазина
├── DeliverySlots[] — слоты доставки
└── Orders[] — заказы в этом магазине
```

**Важно:** Товары и категории привязаны к конкретному магазину через `shop_code`.
