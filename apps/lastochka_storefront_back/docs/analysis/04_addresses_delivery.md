## 🔴 Критические проблемы

### 1. Структура адреса — полное несоответствие

**API подход:** Раздельные поля
```json
{
  "country": "Россия",
  "city": "Москва", 
  "street": "Ленина",
  "houseNumber": "10"
}
```

**Exchange подход:** Одна строка
```json
{
  "address": "Россия, Москва, ул. Ленина, д. 10"
}
```

**Вопросы:**
- Какой формат используется в CRM?
- Нужен ли парсинг адреса?
- Использовать DaData/Яндекс для геокодинга?

**Рекомендации:**
1. Хранить на бэке оба формата: раздельные поля + полная строка
2. При создании адреса: геокодировать для получения координат
3. При синхронизации с Exchange: конкатенировать в `address`

### 2. Координаты (latitude/longitude)
**Проблема:** API не передаёт координаты, Exchange — да.

**Вопросы:**
- Нужны ли координаты для мобильного приложения?
- Для расчёта зоны доставки нужны координаты

**Рекомендация:** Добавить в API:
```json
{
  "latitude": 55.7558,
  "longitude": 37.6173
}
```

### 3. Название адреса (title)
**Проблема:** Exchange имеет `title` ("Дом", "Работа"), API — нет.

**Рекомендация:** Добавить в API поле `title` (nullable).

### 4. Комментарий к адресу
**Проблема:** API имеет `comment`, Exchange — нет.

**Рекомендация:** Хранить локально или добавить в Exchange.

## Сопоставление: Слоты доставки

### API модель

```json
{
  "id": 1,
  "timeSlot": "10:00-12:00"
}
```

### Exchange (DeliverySystem API)

**Запрос:**
```json
{
  "latitude": 55.7558,
  "longitude": 37.6173,
  "date": "2025-01-15"
}
```

**Ответ:**
```json
{
  "slots": [
    {"start": "2025-01-15 10:00:00", "end": "2025-01-15 12:00:00"},
    {"start": "2025-01-15 12:00:00", "end": "2025-01-15 14:00:00"}
  ],
  "min_order_price": 500,
  "shipping_free_from": 1500,
  "shipping_price": 200
}
```

### GAP анализ

| API | DeliverySystem | GAP |
|-----|----------------|-----|
| id | ❌ | Генерировать на бэке |
| timeSlot (string) | start + end (datetime) | Форматировать |
| — | min_order_price | **Добавить** |
| — | shipping_free_from | **Добавить** |
| — | shipping_price | **Добавить** |

**Проблема:** API DeliverySlot слишком простой для реальной логики.

**Рекомендации:**
1. Расширить ответ `getDeliverySlots`:
```json
{
  "slots": [
    {"id": 1, "timeSlot": "10:00-12:00", "date": "2025-01-15"}
  ],
  "minOrderAmount": 500,
  "freeDeliveryFrom": 1500,
  "deliveryPrice": 200
}
```

2. Или создать отдельный endpoint:
```
GET /stores/{storeId}/delivery-info?lat=55.75&lng=37.61&date=2025-01-15
```

## Интеграция с DeliverySystem

### Флоу получения слотов

```
1. Клиент выбирает адрес доставки
2. Frontend отправляет: storeId + координаты адреса + дату
3. Backend вызывает DeliverySystem API
4. Преобразует ответ в формат API
5. Возвращает клиенту
```

### Что нужно для интеграции

1. **Координаты адреса** — нужно геокодирование
2. **API DeliverySystem** — URL, авторизация
3. **Маппинг слотов** — start/end → timeSlot string
4. **Кеширование** — слоты можно кешировать на короткое время
