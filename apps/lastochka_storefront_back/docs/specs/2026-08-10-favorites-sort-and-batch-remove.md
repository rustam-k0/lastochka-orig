# Избранное: сортировка по дате добавления и массовое удаление (MENDEV-4, MENDEV-5)

Контракт изменённого API избранного storefront для мобилки. Описывает, что отдаёт бэкенд. Изменения уже задеплоены на dev.

## Что изменилось

1. `GET /api/v1/favorites` и `GET /api/v1/favorites/product-groups` принимают параметр `sort` — направление сортировки по дате добавления в избранное.
2. Новая ручка `DELETE /api/v1/favorites` — массовое удаление товаров из избранного по списку ID.
3. Новая ручка `DELETE /api/v1/favorites/product-groups` — массовое удаление решений из избранного по списку ID.

## База

| | |
|---|---|
| Endpoint'ы | `GET/DELETE /api/v1/favorites`, `GET/DELETE /api/v1/favorites/product-groups` |
| Dev | `https://store.raz-dev.mendev.ru` |
| Prod | пока нет (dev-стенд) |
| Auth | `Authorization: Bearer <token>` (Sanctum), все ручки только для авторизованных |
| Content-Type | `application/json` |
| Rate limit | нет |

## Ручки

### GET /api/v1/favorites — список избранных товаров

Новый параметр `sort` (существующие `page`, `perPage`, `storeId` не менялись):

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| sort | string | нет | `date_added_desc` — новые сверху (по умолчанию), `date_added_asc` — старые сверху. Нераспознанное значение эквивалентно `date_added_desc` |

Ответ (форма не менялась): `{hasMore: bool, data: Product[], total: int}`.

При равном времени добавления порядок стабилен между страницами (серверный tie-breaker по id).

### GET /api/v1/favorites/product-groups — список избранных решений

Параметр `sort` идентичен товарному: `date_added_desc` (дефолт) / `date_added_asc`.

### DELETE /api/v1/favorites — массовое удаление товаров

| Поле | Тип | Обяз. | Описание | Ограничения |
|---|---|---|---|---|
| productIds | int[] | да | ID товаров для удаления из избранного | 1–500 элементов, каждый — целое число |

Ответ `200`: `{"removed": <int>}` — число реально удалённых записей.

Операция идемпотентна: ID, которых нет в избранном пользователя (в том числе несуществующие товары), молча игнорируются; повторный вызов возвращает `removed: 0`. Существование товаров не проверяется.

### DELETE /api/v1/favorites/product-groups — массовое удаление решений

| Поле | Тип | Обяз. | Описание | Ограничения |
|---|---|---|---|---|
| productGroupIds | int[] | да | ID решений для удаления из избранного | 1–500 элементов, каждый — целое число |

Ответ и поведение идентичны товарной ручке: `{"removed": <int>}`, идемпотентно.

## Коды ответов

| Ситуация | HTTP | Тело |
|---|---|---|
| Успех (включая повтор с теми же ID) | 200 | `{"removed": N}` |
| Без токена | 401 | `{"message": "Unauthenticated."}` |
| `productIds` не передан / пустой / не массив / >500 элементов / нечисловой элемент | 422 | `{"message": "...", "errors": {"productIds": [...]}}` (для нечислового элемента ключ `productIds.N`) |

## Пример

```bash
curl -X DELETE 'https://store.raz-dev.mendev.ru/api/v1/favorites' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"productIds": [1156, 2578, 99999]}'
```

```json
{"removed": 2}
```

## Обратная совместимость

Без параметра `sort` порядок прежний (новые сверху) — существующий клиент работает без изменений. DELETE-ручки новые, ни одна существующая не менялась.
