# Оформление заказа без слотов доставки (MID-256)

Контракт изменённого API для сайта и мобильного приложения клиента (`storefront_back`) и для приложений сборщика/курьера (`delivery_back`). Поведение включается модулем `checkout_without_slots` в админке (Настройки, Модули). При выключенном модуле все ручки работают как раньше.

> **Обновлено 20.08.2026.** Модуль касается только курьерской доставки. Самовывоз из него исключён: клиент выбирает время выдачи в магазине, слот самовывоза остаётся обязательным при любом состоянии модуля. Если ваша реализация прятала выбор времени и для самовывоза, её нужно поправить: иначе оформление самовывоза вернёт 422.

> **Обновлено 21.08.2026.** Слот доставочного заказа в приложениях сборщика и курьера теперь прячет сам бэкенд: `slot_start_date` и `slot_end_date` приходят `null`. Отдельная проверка флага на клиенте для этого больше не нужна, поле просто не отрисовывается, когда пришёл `null`. Пункт 6 ниже переписан.

## Что изменилось

1. `GET /api/v1/app-settings` отдаёт новый флаг `checkoutWithoutSlots` (boolean). При `true` клиент не показывает выбор слота **курьерской доставки** и не запрашивает `GET /stores/{store}/delivery-slots` для выбора времени. Для самовывоза выбор времени показывается всегда, как и раньше.
2. `POST /api/v1/orders`: поле `deliverySlotId` становится необязательным при `checkoutWithoutSlots = true` и `shippingMethod = courier`. Без слота заказ оформляется на ближайшее время. Переданный слот по-прежнему проверяется и сохраняется. При `shippingMethod = pickup` слот обязателен всегда.
3. `POST /api/v1/client-orders` (скрытый маркетплейс): поле `deliverySlots` становится необязательным при `checkoutWithoutSlots = true` и `shippingMethod = courier`. Без слотов создаётся по одному заказу на каждый магазин корзины. При `shippingMethod = pickup` слоты обязательны всегда.
4. Новый ответ 422 `store_closed`: заказ без слота отклоняется, если магазин по своему графику сейчас не принимает заказы.
5. В ответах о заказе (`GET /api/v1/orders/{id}`, список заказов) поля слота (`deliverySlotTimeSlot`, `deliverySlotDate`, для маркетплейса `deliverySlot`) у курьерских заказов без слота равны `null`. У самовывозных заказов они заполнены всегда.
6. GraphQL delivery_back (приложения сборщика/курьера): у доставочного заказа поля `slot_start_date` и `slot_end_date` приходят `null`, когда модуль включён. Показывать нечего: у заказов без слота значение техническое (момент прихода заказа в курьерку), а не время доставки. У заказов самовывоза (`type_id = 1`) слот приходит как раньше и его нужно показывать. Запрос `checkout_without_slots_enabled: Boolean` остаётся и говорит, включён ли модуль, — он нужен, если экран меняет подписи (например «Доставка в ближайшее время» вместо интервала). Прятать поле по этому флагу вручную не требуется.
7. `GET /api/v1/stores/{store}/delivery-slots` и `GET /api/v1/stores/{store}/pickup-slots` не изменились и продолжают отдавать слоты. При `checkoutWithoutSlots = true` клиент прячет выбор времени доставки для любого адреса, ничего дополнительно проверять не нужно. Для самовывоза выбор времени по `pickup-slots` остаётся обязательным шагом чекаута.
8. Адрес в зоне Яндекс-доставки: заявке Яндекса нужен интервал, поэтому бэкенд сам подставляет ближайший доступный слот. Клиент ничего не передаёт и не проверяет `yandexDelivery`. Если доступного времени по адресу сейчас нет, приходит 422 по полю `deliverySlotId` (см. ниже).

## Ручки

### Флаг модуля

```
GET /api/v1/app-settings
```

Публичная, без авторизации. Дёргается при старте приложения.

Ответ 200 (показаны только относящиеся к задаче поля):

```json
{
  "data": {
    "checkoutOptions": [ { "code": "chill_before_delivery", "label": "Охладить перед доставкой" } ],
    "checkoutWithoutSlots": true
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `checkoutWithoutSlots` | boolean | `true`: при курьерской доставке выбор слота скрыть, заказ оформлять без `deliverySlotId`. `false`: прежнее поведение, слот обязателен. На самовывоз флаг не влияет: слот обязателен при любом значении |

### Оформление заказа

```
POST /api/v1/orders
```

Body (показаны поля, связанные с задачей; остальные без изменений):

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `storeId` | integer | да | магазин |
| `addressId` | integer | да для `courier`, нет для `pickup` | адрес доставки |
| `shippingMethod` | string | нет | `courier` (по умолчанию), `pickup`, `cdek`, `russian_post` |
| `deliverySlotId` | integer (Unix timestamp начала слота) | `courier`: **нет при `checkoutWithoutSlots = true`**, да при `false`. `pickup`: **да всегда** | не передан (курьер): заказ на ближайшее время. Передан: проверяется и сохраняется как раньше. Для `pickup` берётся из `GET /stores/{store}/pickup-slots` |
| `paymentType` | string | нет | `cash`, `card` |
| `comment` | string | нет | до 1000 символов |

Ответ 201:

```json
{ "orderId": 1234, "confirmationUrl": null }
```

Ответы 422:

Слот не передан при выключенном модуле (прежнее поведение):

```json
{ "message": "Выберите время доставки", "errors": { "deliverySlotId": ["Выберите время доставки"] } }
```

Слот не передан при самовывозе (при любом состоянии модуля):

```json
{ "message": "Выберите время самовывоза", "errors": { "deliverySlotId": ["Выберите время самовывоза"] } }
```

Магазин сейчас не принимает заказы (только при заказе без слота):

```json
{
  "error": "store_closed",
  "message": "Магазин «Краснояр 1» сейчас не принимает заказы",
  "errors": { "storeId": ["Магазин «Краснояр 1» сейчас не принимает заказы"] }
}
```

Адрес в зоне Яндекс-доставки, слот не передан и доступного времени сейчас нет (Яндексу нужен интервал, бэкенд подставляет ближайший слот, но подставить нечего, например поздно вечером):

```json
{ "message": "По этому адресу сейчас нет доступного времени доставки", "errors": { "deliverySlotId": ["По этому адресу сейчас нет доступного времени доставки"] } }
```

Показать текст пользователю и предложить оформить позже. Показывать выбор слота в этом случае не нужно: слотов всё равно нет.

Для Яндекс-адреса при успешном оформлении в ответах о заказе поля слота будут заполнены (подставленный интервал), для обычной курьерской доставки без слота они `null`. У самовывоза слот всегда заполнен.

Переданный слот недоступен (прежнее поведение):

```json
{ "message": "Слот доставки больше недоступен", "errors": { "deliverySlotId": ["Слот доставки больше недоступен"] } }
```

Остальные коды (401, 404, 422 по корзине, минимальной сумме, оплате) без изменений.

### Оформление заказа в скрытом маркетплейсе

```
POST /api/v1/client-orders
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `addressId` | integer | да | адрес |
| `paymentType` | string | да | `cash`, `card` |
| `shippingMethod` | string | нет | `courier` (по умолчанию), `pickup`, `cdek`, `russian_post` |
| `deliverySlots` | array of `{ storeId, slotId }` | `courier`: **нет при `checkoutWithoutSlots = true`**, да при `false`. `pickup`: **да всегда** | не передан или пустой (курьер): по одному заказу на каждый магазин корзины без слота. Передан: как раньше, должен покрывать все магазины корзины |

Ответ 200 (без изменений):

```json
{ "clientOrderId": "uuid", "subOrderIds": [12, 13], "totalAmount": 1500, "consolidatedStatus": "pending", "confirmationUrl": null }
```

422 `store_closed` для любого из магазинов корзины: формат как у `POST /orders`.

### Карточка и список заказов

```
GET /api/v1/orders/{id}
GET /api/v1/orders
```

Без новых полей. У курьерских заказов без слота:

```json
{ "deliverySlotTimeSlot": null, "deliverySlotDate": null }
```

У заказов в зону Яндекс-доставки, оформленных без слота, поля заполнены подставленным интервалом (например `"deliverySlotTimeSlot": "14:00-16:00"`).

Для маркетплейса (`GET /api/v1/client-orders/{clientOrderId}`): `"deliverySlot": { "date": null, "timeFrom": null, "timeTo": null, "display": null }`.

Отображение «Доставим в течение 15–30 минут» на стороне клиента: текст статический, бэкенд его не отдаёт.

### Приложения сборщика и курьера (GraphQL delivery_back)

```
POST /graphql-delivery
```

```graphql
query { checkout_without_slots_enabled }
```

Ответ:

```json
{ "data": { "checkout_without_slots_enabled": true } }
```

Без `@guard`, доступен любому авторизованному пользователю курьерки. При `true` поля `slot_start_date` / `slot_end_date` не показывать у доставочных заказов: там они равны моменту оформления. У заказов самовывоза (`type_id = 1`) слот реальный, его показываем как обычно.
