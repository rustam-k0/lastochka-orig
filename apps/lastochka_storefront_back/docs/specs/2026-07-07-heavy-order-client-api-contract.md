# Тяжёлый заказ / совместная доставка — контракт клиентского API

Фича за модулем `heavy_orders` (админка → Настройки → Модули). При выключенном
модуле `isHeavy=false` для НОВЫХ заказов и корзины — клиент ничего не показывает.
Заказы, созданные при включённом модуле, сохраняют признак и счётчик курьеров:
in-flight совместные доставки корректно довозятся и остаются видимыми клиенту.

## Корзина / чекаут

`GET /api/v1/cart` (standard-режим):
| Поле | Тип | Описание |
|---|---|---|
| `weightTotal` | float\|null | Общий вес корзины, КГ (существующее поле) |
| `isHeavy` | bool | НОВОЕ: хотя бы одна store-группа превышает порог магазина |
| `storeGroups[].weightTotal` | float\|null | Вес группы, КГ (существующее) |
| `storeGroups[].isHeavy` | bool | НОВОЕ: вес группы строго превышает порог её магазина |

UI: при `isHeavy=true` на этапе оформления показать вес + плашку «Тяжелый заказ»
+ информационное сообщение (текст фиксирован):
> Ваш заказ тяжелый. Для доставки может быть назначено несколько курьеров.

## Детали заказа

Поля фичи возвращаются в обоих режимах. Мобилка mendev работает в **standard-режиме**
и получает детали заказа через `GET /api/v1/orders/{orderId}` — это основной эндпоинт.
Эндпоинт `GET /api/v1/client-orders/{clientOrderId}` — только для **marketplace-режима**
(за middleware `marketplace.mode`); в standard-режиме он недоступен (403/404).

### Основной эндпоинт (standard-режим, mendev)

`GET /api/v1/orders/{orderId}` (ресурс `OrderResource`, ответ обёрнут в `data`):
| Поле | Тип | Описание |
|---|---|---|
| `data.weightTotal` | float\|null | НОВОЕ: вес заказа, КГ (сумма по корневым позициям; null если вес недоступен) |
| `data.isHeavy` | bool | НОВОЕ: признак «Тяжелый заказ» |
| `data.couriersCount` | int | НОВОЕ: число курьеров, задействованных в доставке |
| `data.isJointDelivery` | bool | НОВОЕ: `couriersCount > 1` — совместная доставка |

Те же поля отдаются в списке заказов `GET /api/v1/orders` (`data[].isHeavy` и т.д.)
и в активном заказе `GET /api/v1/orders/active` (`data.isHeavy` и т.д.) — тот же
`OrderResource`.

### Marketplace-режим

`GET /api/v1/client-orders/{clientOrderId}` (за middleware `marketplace.mode`,
ресурс `ClientOrderResource`, ответ БЕЗ обёртки `data`):
| Поле | Тип | Описание |
|---|---|---|
| `weightTotal` | float\|null | Вес заказа, КГ (существующее) |
| `isHeavy` | bool | НОВОЕ: признак «Тяжелый заказ» (хотя бы один sub-order тяжёлый) |
| `couriersCount` | int | НОВОЕ: макс. число курьеров среди sub-order'ов |
| `isJointDelivery` | bool | НОВОЕ: `couriersCount > 1` — совместная доставка |

UI: при `isHeavy=true` — плашка «Тяжелый заказ»; при `isJointDelivery=true` —
сообщение (текст фиксирован):
> Заказ доставляют несколько курьеров.

Для клиента заказ остаётся единым: один заказ, один адрес, один статус, одна
итоговая стоимость — ничего в существующем контракте не меняется.
