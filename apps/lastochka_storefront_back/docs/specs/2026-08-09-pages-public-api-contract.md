# Статичные страницы: публичный API

Дата: 2026-08-09
Модуль: mendev_storefront_back
Аудитория: разработчики сайта и мобильного приложения

Страницы ведутся в админ-панели и приезжают в витрину через шину событий.
Авторизация для чтения не требуется. Один и тот же ответ получают и сайт, и приложение.

## Коды системных страниц

На эти коды можно завязывать ссылки в интерфейсе: они не меняются и страницы с такими кодами не удаляются.

| Код | Назначение |
|---|---|
| `privacy-policy` | Политика конфиденциальности |
| `public-offer` | Публичная оферта |

Неизменность кода не означает постоянную доступность страницы: системные страницы тоже создаются черновиком
и до ручной публикации администратором отдают `404`, как и любая другая неопубликованная страница.

Остальные страницы админ создаёт сам, их коды произвольны. Список актуальных кодов всегда можно получить первым эндпоинтом.

## GET /api/v1/pages

Список опубликованных страниц в порядке отображения. Содержимое не передаётся.

```json
{
  "data": [
    {
      "id": 3,
      "slug": "privacy-policy",
      "title": "Политика конфиденциальности",
      "position": 1,
      "publishedAt": "2026-08-09T12:00:00+03:00",
      "updatedAt": "2026-08-09T12:30:00+03:00"
    }
  ]
}
```

`position` может быть `null`: такие страницы идут в конце списка.

`publishedAt` может быть пустым (`null`). Не полагайтесь на то, что оно всегда заполнено.

## GET /api/v1/pages/{slug}

Карточка страницы по коду. Неопубликованная, удалённая или несуществующая страница отдаёт `404`.

Код страницы (`slug`) в пути запроса принимает только латиницу в нижнем регистре, цифры и дефис:
`[a-z0-9-]+`. Код с другими символами (заглавные буквы, подчёркивание, кириллица) не совпадёт с маршрутом
и тоже приведёт к `404`.

```json
{
  "data": {
    "id": 3,
    "slug": "privacy-policy",
    "title": "Политика конфиденциальности",
    "content": {
      "time": 1754730000000,
      "blocks": [
        { "type": "header", "data": { "text": "1. Общие положения", "level": 2 } },
        { "type": "paragraph", "data": { "text": "Настоящая политика описывает..." } }
      ],
      "version": "2.29.1"
    },
    "metaTitle": null,
    "metaDescription": null,
    "publishedAt": "2026-08-09T12:00:00+03:00",
    "updatedAt": "2026-08-09T12:30:00+03:00"
  }
}
```

`metaTitle` и `metaDescription` нужны сайту для выдачи в поиске, приложение их игнорирует.

`publishedAt` здесь тоже может быть пустым (`null`) по той же причине, что и в списке.

## Формат содержимого

`content` это документ редактора EditorJS: объект с массивом `blocks`. Каждый блок имеет `type` и `data`.
Если содержимое повреждено, придёт `{"blocks": []}`, поэтому обрабатывать пустой массив блоков нужно штатно.

Типы блоков, которые может создать администратор:

| type | Что внутри `data` |
|---|---|
| `paragraph` | `text` (строка, может содержать инлайновую разметку) |
| `header` | `text`, `level` (1..6) |
| `list` | `style` (`ordered` или `unordered`), `items` (массив строк) |
| `table` | `content` (массив строк таблицы, каждая строка массив ячеек) |
| `quote` | `text`, `caption`, `alignment` |
| `delimiter` | пустой объект |
| `image` | `file.url`, `caption`, `withBorder`, `withBackground`, `stretched` |
| `warning` | `title`, `message` |
| `code` | `code` |
| `raw` | `html` |
| `embed` | `service`, `source`, `embed`, `width`, `height`, `caption` |
| `linkTool` | `link`, `meta.title`, `meta.description`, `meta.image.url` |

Неизвестный тип блока клиент должен пропускать, а не падать: набор плагинов редактора может пополниться.

## Инлайновая разметка

Внутри `text` встречаются теги `<b>`, `<i>`, `<a href="...">`, `<mark>`, `<code>`, `<br>`.
Источник доверенный (админ-панель), но при вставке в DOM разметку нужно санитайзить, а в мобильном приложении рендерить выбранным HTML-парсером.

## Кеширование

Ответы не кешируются на стороне сервера. Ориентир для клиентского кеша это поле `updatedAt`.

Важно: `updatedAt` это момент, когда витрина обработала событие с изменениями страницы, а не момент правки
в админ-панели. Обычно разница исчисляется секундами, но при задержке доставки события через очередь
времена могут разойтись заметнее. Если нужен именно момент правки в админке, этот эндпоинт для этого не подходит.
