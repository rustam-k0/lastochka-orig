# Публичный API раздела «Работа в компании» (MID-177)

Контракт нового публичного API для клиентов (веб-сайт и мобильное приложение). Описывает, что принимает и отдаёт бэкенд storefront. Контент раздела заполняет администратор в админ-панели (раздел «Работа в компании»), отклики уходят письмом на почту заказчика и в базе не сохраняются.

## Что предоставляется

1. `GET /api/v1/vacancies` — список опубликованных вакансий в порядке отображения.
2. `GET /api/v1/vacancies/{id}` — карточка вакансии с полным описанием.
3. `POST /api/v1/vacancies/{id}/responses` — отправка отклика с резюме (multipart).

## База

| | |
|---|---|
| Endpoints | `GET /api/v1/vacancies`, `GET /api/v1/vacancies/{id}`, `POST /api/v1/vacancies/{id}/responses` |
| Dev | `https://store.raz-dev.mendev.ru` |
| Prod | прод-стенда пока нет |
| Протокол | REST, JSON |
| Content-Type | ответы `application/json`; тело отклика — `multipart/form-data` |
| Auth | не требуется, все три ручки публичные |
| Rate limit | `GET` — нет; `POST .../responses` — 5 запросов за 60 минут с одного IP |
| OpenAPI-дока | `https://store.raz-dev.mendev.ru/docs/api` (группа Vacancies) |

## Ручки

### GET /api/v1/vacancies: список вакансий

Параметров нет: ни query-аргументов, ни пагинации, ни фильтров. Сервер всегда возвращает полный список опубликованных вакансий одним ответом.

Форма ответа:

```json
{
  "data": [
    {
      "id": 1,
      "title": "Повар горячего цеха",
      "city": "Москва",
      "workFormat": "office",
      "workFormatLabel": "Офис",
      "employmentType": "full",
      "employmentTypeLabel": "Полная занятость",
      "salary": "80 000 ₽",
      "shortDescription": "Готовим полуфабрикаты и блюда собственного производства"
    }
  ]
}
```

### GET /api/v1/vacancies/{id}: карточка вакансии

| Параметр | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | int (path) | да | ID вакансии из списка |

Форма ответа:

```json
{
  "data": {
    "id": 1,
    "title": "Повар горячего цеха",
    "city": "Москва",
    "workFormat": "office",
    "workFormatLabel": "Офис",
    "employmentType": "full",
    "employmentTypeLabel": "Полная занятость",
    "workSchedule": "3/3",
    "salary": "80 000 ₽",
    "shortDescription": "Готовим полуфабрикаты и блюда собственного производства",
    "description": "Ищем повара для приготовления полуфабрикатов и готовых блюд...",
    "responsibilities": "Приготовление блюд по технологическим картам",
    "requirements": "Опыт работы от полугода",
    "conditions": "Оформление медкнижки за счёт компании",

    "linkUrl": "https://hh.ru/vacancy/123456"
  }
}
```

### POST /api/v1/vacancies/{id}/responses: отклик на вакансию

Тело — `multipart/form-data`.

| Поле | Тип | Обяз. | Описание | Ограничения |
|---|---|---|---|---|
| `name` | string | да | Имя кандидата | до 255 символов |
| `phone` | string | да | Телефон, формат свободный | до 32 символов |
| `email` | string | да | Электронная почта | валидный email, до 255 символов |
| `comment` | string | нет | Сопроводительное письмо | до 2000 символов |
| `resume` | file | да | Файл резюме, ровно один | форматы `pdf`, `doc`, `docx`; до 5 МБ |
| `personalDataConsent` | boolean | да | Согласие на обработку персональных данных | принимается только истинное значение (`1`, `true`, `"on"`, `"yes"`) |
| `source` | string | нет | Источник отправки | `mobile` или `website`; по умолчанию `website` |

Форма успешного ответа:

```json
{ "message": "Отклик успешно отправлен" }
```

Допустимые форматы файла и предельный размер задаются настройкой стенда (`VACANCY_RESUME_EXTENSIONS`, `VACANCY_RESUME_MAX_SIZE_KB`). Значения выше — те, что стоят на dev.

## Типы

| Поле | Тип | null | Описание |
|---|---|---|---|
| `id` | int | нет | ID вакансии |
| `title` | string | нет | Наименование вакансии |
| `city` | string | да | Город, в котором открыта вакансия |
| `workFormat` | string | да | Код формата работы: `office`, `remote`, `hybrid`, `field` |
| `workFormatLabel` | string | да | Название формата работы на русском; `null` вместе с `workFormat` |
| `employmentType` | string | да | Код типа занятости: `full`, `part`, `temporary`, `other` |
| `employmentTypeLabel` | string | да | Название типа занятости на русском; `null` вместе с `employmentType` |
| `workSchedule` | string | да | График работы (только в карточке) |
| `salary` | string | да | Уровень дохода строкой, как ввёл администратор |
| `shortDescription` | string | да | Краткое описание для списка |
| `description` | string | да | Полное описание (только в карточке) |
| `responsibilities` | string | да | Обязанности (только в карточке) |
| `requirements` | string | да | Требования (только в карточке) |
| `conditions` | string | да | Условия (только в карточке) |
| `linkTitle` | string | да | Название ссылки на вакансию на внешнем ресурсе (только в карточке) |
| `linkUrl` | string | да | Адрес ссылки на вакансию, например на hh.ru (только в карточке) |

Все текстовые поля — plain text в том виде, как их ввёл администратор, могут содержать переводы строк `\n`. HTML и markdown сервер не генерирует.

## Ссылка на вакансию на внешнем ресурсе (MID-257)

В карточке вакансии может быть заполнена пара полей `linkTitle` и `linkUrl`. Это ссылка на ту же вакансию на стороннем ресурсе, чаще всего на hh.ru.

Правила для клиента:

1. Блок со ссылкой показывается, только если `linkUrl` не пустой. Если `linkUrl` равен `null`, ссылку не рисуем совсем, даже когда `linkTitle` заполнен.
2. Подписью ссылки служит `linkTitle`. Если он пустой, а `linkUrl` заполнен, клиент подставляет свою подпись по умолчанию, например «Смотреть вакансию».
3. `linkUrl` всегда абсолютный адрес со схемой `http` или `https` (проверяется на стороне админки). Открывать во внешнем браузере или новой вкладке.
4. Ссылка не заменяет форму отклика: обе возможности показываются одновременно, если ссылка заполнена.

## Поведение сервера

| Условие | Что отдаёт сервер |
|---|---|
| Сортировка списка | По `position` по возрастанию; вакансии без позиции в конце списка; при равных позициях по `id` по возрастанию |
| Вакансия не опубликована, снята с публикации или удалена | В список не попадает; карточка и отклик отдают 404 |
| Ни одной опубликованной вакансии | HTTP 200, `{"data": []}` |
| Отклик на неопубликованную вакансию | HTTP 404, письмо не отправляется |
| Отправка письма завершилась ошибкой | HTTP 502; отклик не считается принятым |
| Успешный отклик | Письмо с анкетой и приложенным резюме уходит на единый адрес заказчика; ни отклик, ни резюме, ни контакты кандидата в базе не сохраняются и в админ-панели не отображаются |
| Содержимое письма | Название вакансии, имя, телефон, почта, комментарий при наличии, дата и время отправки, источник отправки, вложенный файл резюме |
| Администратор изменил вакансию в админке | Изменения доезжают в storefront асинхронно (RabbitMQ, события `vacancy.*`), обычно в пределах нескольких секунд |

## Коды ответов

| Ситуация | HTTP | Тело |
|---|---|---|
| Успех списка или карточки | 200 | `{"data": ...}` |
| Успешно отправленный отклик | 200 | `{"message": "Отклик успешно отправлен"}` |
| Вакансия не найдена или не опубликована | 404 | JSON с полем `message` |
| Анкета заполнена некорректно (нет резюме, неверный формат файла, превышен размер, нет согласия) | 422 | `{"message": "...", "errors": {"resume": ["..."], ...}}` |
| Превышен лимит отправок с одного IP | 429 | JSON с полем `message`, заголовок `Retry-After` |
| Письмо с откликом отправить не удалось | 502 | `{"message": "Не удалось отправить отклик. Попробуйте ещё раз позже."}` |
| Метод не поддерживается ручкой | 405 | JSON с полем `message` |

## Пример

```bash
curl -X POST 'https://store.raz-dev.mendev.ru/api/v1/vacancies/1/responses' \
  -H 'Accept: application/json' \
  -F 'name=Иван Иванов' \
  -F 'phone=+7 999 123-45-67' \
  -F 'email=ivan@example.com' \
  -F 'comment=Работал поваром три года' \
  -F 'personalDataConsent=1' \
  -F 'source=mobile' \
  -F 'resume=@/path/to/resume.pdf'
```

```json
{ "message": "Отклик успешно отправлен" }
```

Ответ при некорректной анкете:

```json
{
  "message": "Прикрепите резюме (and 1 more error)",
  "errors": {
    "resume": ["Прикрепите резюме"],
    "personalDataConsent": ["Необходимо согласие на обработку персональных данных"]
  }
}
```

## Обратная совместимость

API новый, существующие ручки не менялись. Поля `workFormatLabel` и `employmentTypeLabel` дублируют коды `workFormat` и `employmentType` в человекочитаемом виде — клиент может использовать любой из вариантов. Новых обязательных заголовков и параметров у существующих ручек не появилось.
