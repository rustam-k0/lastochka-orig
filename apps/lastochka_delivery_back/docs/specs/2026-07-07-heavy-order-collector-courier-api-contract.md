# Тяжёлый заказ / совместная доставка — контракт для приложений сборщика и курьера

Фича за модулем `heavy_orders`. Гейт для мобильных экранов:
`query { heavy_orders_enabled }` → Boolean (без аргументов). При false —
не показывать плашки и экран назначения курьеров.

## Новые поля Order (GraphQL /graphql)

| Поле | Тип | Описание |
|---|---|---|
| `is_heavy` | Boolean | Плашка «Тяжелый заказ». Ставится при оформлении (чекаут-вес), пересчитывается при завершении сборки |
| `couriers_count` | Int | Число курьеров, задействованных в доставке. >1 → плашка «Совместная доставка» (курьер) |
| `total_weight` | Int | (существующее) Вес заказа в ГРАММАХ; до сборки — чекаут-оценка, после — фактический |
| `is_weight_partial` | Boolean | (существующее) Вес учитывает не все позиции |

Сборщик видит `is_heavy`/`total_weight` уже в списке заказов (до взятия в работу).

## Назначение курьеров сборщиком (новый экран после завершения сборки)

1. `query { shift_couriers { id name surname phone } }` — курьеры на смене
   магазина сборщика (ability collectorOnShift).
2. `mutation { DeliveryAssignCouriers(order_id: Int!, courier_ids: [Int!]!) { code message } }`
   - обычный заказ: ровно ОДИН id в courier_ids; повторное назначение → ошибка
     «Заказ уже был взят в доставку»;
   - тяжёлый заказ (`is_heavy=true`): один и более id; можно ДОБАВИТЬ курьера,
     когда заказ уже в доставке (статус 4);
   - модуль выключен → ошибка «Функция „Тяжёлые заказы" отключена»;
   - самовывоз → ошибка.
   Назначение запускает доставку у курьера (или ставит заказ в хвост его маршрута,
   если рейс уже начат) и шлёт курьеру push `order_assigned`.

Самостоятельное взятие заказа курьером (`DeliveryTakeOrder`) работает как раньше;
для тяжёлого заказа второй курьер тоже может взять заказ сам (в т.ч. когда заказ
уже в доставке). Ошибка «Вы уже назначены на этот заказ» — при повторном взятии.

## Совместное завершение (курьер)

- Первый курьер, завершивший доставку (`DeliveryFinish`), закрывает заказ для клиента.
- Остальным назначения закрывает система: их `delivery_order` → статус 4 (Завершена),
  приходит push `{type: "order_closed_by_system", order_id}` — приложение должно
  обновить список (заказ пропадает из активных).
- Возвраты/расчёты выполняет только завершающий курьер — товары между курьерами
  в системе не распределяются (распределение пакетов физическое).
- Отмена заказа любым участником закрывает назначения всех курьеров
  (push тот же `order_closed_by_system`).

## Push-уведомления (data.type)

| type | Кому | Когда |
|---|---|---|
| `order_assigned` | курьеру | сборщик/админ назначил заказ (существующее) |
| `order_ready_for_delivery` | курьерам смены | заказ собран (существующее) |
| `order_closed_by_system` | остальным курьерам | НОВОЕ: заказ завершён/отменён другим участником |
