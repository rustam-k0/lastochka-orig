# Назначение курьера сборщиком (модуль courier_assignment): контракт для приложений сборщика и курьера

Platrum 12183 / MID-151. Фича за модулем `courier_assignment` («Настройки, Модули» в АП).
Все запросы: GraphQL `/graphql-delivery`, авторизация Sanctum Bearer-токеном.

Гейт для мобильных экранов:
`query { courier_assignment_enabled }` возвращает Boolean (без аргументов, без авторизации).
При false приложение работает как раньше: ничего из описанного ниже не показывать.

Смысл фичи: сборщик по завершении сборки назначает одного курьера из списка
работающих сейчас. Курьеры видят только назначенные им заказы, общий список
собранных заказов им недоступен, самостоятельное взятие заказа отключено.

## Приложение сборщика

1. После успешного `AssemblyFinish` (для заказов с доставкой курьером, не самовывоз)
   показать кнопку «Назначить курьера». Экран тот же, что во флоу «Тяжёлый заказ»,
   но теперь для ВСЕХ заказов: если `courier_assignment_enabled` = true, кнопка
   нужна независимо от `is_heavy` и от `heavy_orders_enabled`.
2. Список курьеров: `query { shift_couriers { id name surname phone } }`.
   Это курьеры с открытой сменой в магазине смены сборщика (ability collectorOnShift).
3. Назначение: `mutation { DeliveryAssignCouriers(order_id: Int!, courier_ids: [Int!]!) { code message } }`
   - обычный заказ: ровно ОДИН id в courier_ids;
   - два и более id для обычного заказа: ошибка «Несколько курьеров можно назначить только на тяжёлый заказ»;
   - повторное назначение: ошибка «Заказ уже был взят в доставку» (переназначение делает админ из АП);
   - самовывоз: ошибка «Заказ оформлен на самовывоз и не назначается курьеру»;
   - заказ не в статусе «Собран»: ошибка «Заказ еще не готов к доставке»;
   - оба модуля (courier_assignment и heavy_orders) выключены: ошибка «Назначение курьеров отключено».
4. Назначение сразу запускает доставку у курьера (или ставит заказ в хвост его
   маршрута, если рейс уже начат) и шлёт курьеру push `order_assigned`.
   Это существующее поведение, оно не менялось.
5. Кейс «сборщик закрыл приложение, не назначив курьера»: заказ остаётся в
   статусе «Собран» и курьерам не виден. Сборщик может назначить курьера позже
   с экрана заказа, либо это сделает админ из АП.

## Тяжёлые заказы (совместная доставка) входят в этот модуль

Флоу тяжёлых заказов активен при heavy_orders ИЛИ courier_assignment, отдельно
включать heavy_orders не требуется:

- Признак `is_heavy` считается на чекауте по порогу веса магазина и
  пересчитывается по фактическому весу при завершении сборки.
- Для заказа с `is_heavy` = true сборщик может выбрать НЕСКОЛЬКИХ курьеров в
  `DeliveryAssignCouriers` (courier_ids из двух и более id) и добавить курьера,
  когда тяжёлый заказ уже в пути (статус «В доставке»).
- Условие показа мультивыбора на экране назначения:
  `(heavy_orders_enabled ИЛИ courier_assignment_enabled) && is_heavy`.
- Совместное завершение как в контракте
  `2026-07-07-heavy-order-collector-courier-api-contract.md`: первый
  завершивший курьер закрывает заказ, остальным приходит push
  `order_closed_by_system`.
- Отличие от чистого heavy-флоу: самостоятельное взятие заказа вторым курьером
  (`DeliveryTakeOrder`) при включённом courier_assignment недоступно, второго
  курьера добавляет сборщик или администратор.

## Приложение курьера

1. Общий список заказов (`orders_paginate`, в т.ч. со status «Собран») на
   бэкенде отдаёт курьеру ТОЛЬКО заказы, назначенные ему (включая заказы в
   хвосте его маршрута и доставленные им сегодня). Чужие и неназначенные
   заказы в выдачу не попадают. Точечный `order(id)` для чужого заказа
   возвращает null.
   Рекомендация приложению: при `courier_assignment_enabled` = true скрыть
   вкладку/экран общего списка собранных заказов или показывать её как
   «Назначенные мне».
2. `DeliveryTakeOrder` (самостоятельное взятие) при включённом модуле не
   работает: попытка взять свободный заказ возвращает ошибку «Заказы назначает
   сборщик». Примечание: валидация выполняется раньше модульного гейта, поэтому
   для занятого заказа или начатого рейса могут прийти обычные валидаторные
   тексты («Заказ уже был взят в доставку» и т.п.); взятие заблокировано в любом
   случае. Кнопку «Взять заказ» не показывать.
3. Рейс курьера работает без изменений: `delivery_orders`, `DeliveryStart`,
   `DeliveryArrived`, `DeliveryFinish`, приоритеты, отмены. Заказ появляется у
   курьера после назначения сборщиком или админом (push `order_assigned`).

## Push-уведомления (data.type)

| type | Кому | Поведение при включённом модуле |
|---|---|---|
| `order_assigned` | назначенному курьеру | приходит при назначении (без изменений) |
| `order_ready_for_delivery` | курьерам смены | НЕ приходит (общий список скрыт, пуш отключён) |

## Тексты ошибок (для матчинга в приложении)

- «Назначение курьеров отключено» (оба модуля выключены)
- «Заказы назначает сборщик» (self-take при включённом модуле)
- «Заказ уже был взят в доставку», «Заказ еще не готов к доставке»,
  «Заказ оформлен на самовывоз и не назначается курьеру»,
  «Несколько курьеров можно назначить только на тяжёлый заказ»,
  «Пользователь не является курьером» (существующие, без изменений)

## Отличия от флоу «Тяжёлый заказ»

| Аспект | heavy_orders | courier_assignment |
|---|---|---|
| Какие заказы назначаются сборщиком | все (кнопка в мобилке была только для тяжёлых) | все |
| Число курьеров | 1..N для тяжёлого, 1 для обычного | 1..N для тяжёлого, 1 для обычного |
| Признак is_heavy (чекаут + пересчёт при сборке) | активен | активен |
| Видимость общего списка у курьера | полная | только назначенные |
| Self-take курьером | разрешён (вкл. второго курьера heavy) | запрещён |
| Пуш `order_ready_for_delivery` | приходит | не приходит |

## Аддендум (2026-07-18): назначение больше не стартует доставку

При включённом `courier_assignment_enabled` назначение курьера (сборщиком через `DeliveryAssignCouriers` или админом из панели) НЕ запускает доставку автоматически. Заказ после назначения остаётся в статусе `assembled`. В админ-панели он отображается как «Назначен курьер».

Что это значит для приложения курьера:

1. Курьер получает пуш `order_assigned` и видит назначенный заказ в списке (как раньше).
2. Чтобы начать доставку, курьер обязан нажать «Начать доставку» (mutation `DeliveryStart`). Только после этого заказ переходит в `in_delivery`.
3. Экран старта рейса обязателен в флоу курьера при включённом флаге: без нажатия заказ останется назначенным и в доставку не перейдёт.

Для приложения сборщика изменений нет: флоу «завершил сборку, назначил курьера» прежний.
